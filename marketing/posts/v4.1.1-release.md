# Fetch PHP v4.1.1 — verified maintenance fixes

**Publication draft — not yet released.** Replace this notice only after the
`4.1.1` tag is published, GitHub Actions passes and Composer indexes the tag.

Fetch PHP's next patch release focuses on reliability, portability, and
safer HTTP diagnostics. This update builds on the Guzzle-powered,
JavaScript-inspired API introduced in earlier versions.

## Fixes already merged to main

- Explicit test allowlists no longer allow unrelated requests to escape
  network fakes (PR #191).
- File-backed cache entries remain available for stale response policies;
  per-request shared-cache TTL selection is respected (PR #190).
- The global `fetch()` helper now honors bearer tokens without overwriting
  explicit Authorization headers (PR #192).
- User-provided redirect callbacks are preserved alongside Fetch lifecycle
  events (PR #193).
- A configurable size limit bounds streamed response line buffering
  (PR #194).
- The unnecessary `ext-pcntl` platform requirement is removed, improving
  portability and allowing Windows Composer installs (PR #195).

## Install once published

```sh
composer require jerome/fetch-php:^4.1
```

See the [source](https://github.com/Thavarshan/fetch-php) and
